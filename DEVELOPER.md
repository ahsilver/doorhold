# DoorHold — developer notes
Hosting: Cloudflare Worker `_worker.js` + D1 (DB) + R2 (FILES), declared in site/wrangler.toml; static SPA (index.html, app.js, app.css).
Deploy: `npx wrangler deploy` from site/ (bump ?v= in index.html so browsers pick up new JS/CSS).
Local dev: node --no-warnings test/dev.mjs site 8787  (node:sqlite D1 shim at /tmp/pmdev/dev.db, R2 shim /tmp/pmdev/r2). Delete dev.db to reseed.
Tests: test/e2e.py BASE OUT (env PM_CREDS json {role:[email,pw]}, PM_PHOTO jpg) — full phone flow; test/smoke.py visits every page.
Demo logins: the seed stores PBKDF2 hashes only; put the demo passwords in a local demo-logins.txt (not committed) for tests (env PM_DEMO_LOGINS). Manager > More > Reset demo data re-seeds.
Seed is relative to today's date (6 months history, America/New_York). Money in cents. Journal (double entry: journal + jlines), chart of accounts constant ACCTS.
Bank: CSV/OFX/QFX import -> autoMatch (amount exact, date ±10d, payee name/check# bonus) -> rules -> manual review. Plaid path coded in bankFeedRoute, off unless PLAID_CLIENT_ID/PLAID_SECRET env.
Payments: PROCESSORS.demo active; PROCESSORS.stripe coded (PaymentIntents) but only used if STRIPE_SECRET_KEY + PAYMENTS_LIVE=1.


## v2 — assistant, Buildium-parity pass, utilities, closing import
- **Assistant / command bar** (`m/assist/parse`, `m/assist/confirm`, `m/assist/log`, `m/assist/log/:id/undo`): a bar on every Manager screen (+ mic via Web Speech API where the browser has it). `ruleParse()` (built-in grammar + fuzzy matching of property address, unit, tenant, vendor, bank last-4, dates, amounts, method/check #) always runs; `aiExtract()` optionally refines it when an AI key exists. `resolveDraft()` asks follow-up questions or returns a confirm card; `executeDraft()` posts through the same `post()` journal path as the manual screens; every confirmed action is in `ai_log` with an undo that voids the entries (`undoResult`).
  Intents: payment, charge (late fee/other), credit, expense (paid vendor), bill, recurring_bill, deposit (other income), owner_draw, contribution, rent_change (rent_changes table, applied on the effective date), work_order, new_tenant, task, announcement, utility_bill, match_bank, query (who owes / tenant balance / bank balances).
- **AI provider (pluggable)**: Manager › More › Assistant settings stores `ai_provider` (openai|anthropic|off), `ai_key` (server-side in D1 settings, never returned by the API) and `ai_model`. Env vars `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` (and `AI_BASE_URL` for a proxy) also work if the host ever supports Worker secrets. Default: built-in parser only.
- **Chart of accounts** is now a table (`gl_accounts`), Buildium-style defaults, ids 1-51 permanent; add/rename/renumber/deactivate in Money › General ledger. `loadAccounts()` refreshes the in-memory `AC`/`ACBYID`/`BANKGL` maps on every request. Bank accounts can be added (Money › + Add account), each gets its own 10xx GL account. Import of a real Buildium chart: insert rows into gl_accounts (code, name, type).
- **Bills / AP** (`bills`, `recurring_bills`, cash basis: paying a bill posts an `expense`), **Budgets** (`budgets`, budget vs actual), **Tasks**, **Announcements** (shown on tenant portal home).
- **Utility billing** (`utility_accounts`, `utility_bills`): each bill charges the tenant ledger (4800 Utility Reimbursement Income, memo "Water bill <period> (due <10th>)"), tenant sees it in the portal with View bill + demo Pay; "Paid to provider" posts an expense to 6210 Water & Sewer with confirmation # and card last-4. Tenant due day = setting `utility_due_day` (default 10).
- **External utility API** (for an outside automation): `Authorization: Bearer <token>` (token created in Money › Water bills › Create API token; stored as SHA-256 in settings `ext_api_token_hash`; or env `UTILITY_API_TOKEN`).
  - `GET /api/ext/utility/accounts` — utility accounts with property, unit, tenant, open bills
  - `GET /api/ext/utility/bills[?provider_status=unpaid|paid|overdue]`, `GET /api/ext/utility/bills/:id`
  - `POST /api/ext/utility/bills` `{account_no | utility_account_id, amount, period_start, period_end, bill_date, provider_due, pdf_base64, filename}` — creates (201) or returns the existing bill for the same account+amount+period (200, attaches the PDF if the existing one had none); charges the tenant automatically.
  - `POST /api/ext/utility/bills/:id/paid` `{date, amount, confirmation, card_last4, bank_account_id?}` — records paid to provider (GL expense).
- **Closing import** (Money › Import closing): browser extracts the PDF text with vendored pdf.js (`/vendor/`, `closing-extract.js`), server parses with `parseClosingText()` (rule-based ALTA / HUD-1 / CD, + optional AI), review screen, then `closingConfirm()` creates property/unit(s), optional water account, attaches the PDF, and posts one balanced journal (Dr 1500 Buildings & Land incl. capitalized costs, 1510 Loan Costs, 1300 Prepaids, 1310 Escrow, ±6400 tax proration; Cr 2500 Mortgage Payable, cash from the chosen bank or 3100 Owner Contribution). Scanned PDFs (no text layer) need manual entry.
- **Migration** `migrateV2()` runs once (meta key `v2`) as one atomic D1 batch with precomputed ids: chart, Chase ••2306, 4 Trenton NJ demo houses with Trenton Water Works accounts and bills, AP/recurring bills, tasks, announcement, budget.
- Tests: `node --test test/assistant.test.mjs` (in-memory SQLite D1 shim, real worker); UI: `test/assist_ui.py`, `test/closing_ui.py` (Playwright, phone viewport). Dev env vars for local AI test: `PM_ENV='{"OPENAI_API_KEY":"…","AI_BASE_URL":"…"}' node test/dev.mjs site 8791`.
